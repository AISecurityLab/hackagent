# Installation

Get HackAgent up and running in seconds.

## Quick Install

### Requirements

- **Python 3.10+**
- **pip**

### Production Installation
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install hackagent
```

### Optional extras

`pip install hackagent` installs the SDK, the CLI, and a local SQLite store. `hackagent --version` and `hackagent --help` run from that install. Technique classes stay unloaded until a command uses them, so those two flags do not need `[rag]` or `[vision]`.

A bare install does not open the terminal UI. `hackagent` with no subcommand needs Textual (`hackagent/interfaces/cli/bootstrap.py`):

```bash
pip install 'hackagent[tui]'
```

Some attacks still need an extra when they run. h4rm3l constructs its decorators with NumPy from `[rag]`. The RAG attack and AutoDAN-Turbo load FAISS and NumPy from the same extra. MML loads Pillow from `[vision]`. HarmBench Hub datasets need the `hf` extra (`pip install 'hackagent[hf]'`). `import hackagent` does not load Textual, Flask, or Click. The base install does not include Textual, Flask, Playwright, FAISS, NumPy, Pillow, or the Hugging Face `datasets` library.

| Extra | Command | Unlocks |
| --- | --- | --- |
| `tui` | `pip install 'hackagent[tui]'` | Textual for `hackagent` / `hackagent tui`. Not required for `--version` or `--help` |
| `web` | `pip install 'hackagent[web]'` | Local dashboard (`hackagent web`): Flask and the dashboard bundle |
| `browser` | `pip install 'hackagent[browser]'` | Playwright, for `hackagent scan` and the browser adapter |
| `rag` | `pip install 'hackagent[rag]'` | FAISS and NumPy. h4rm3l decorator construction, the RAG attack, and AutoDAN-Turbo. Not required for `--version` or `--help` |
| `vision` | `pip install 'hackagent[vision]'` | Pillow, for the MML attack. Not required for `--version` or `--help` |
| `hf` | `pip install 'hackagent[hf]'` | Hugging Face `datasets`, for presets and Hub datasets |

You can add an extra at any time. Release binaries already include these libraries.

[`hackagent web`](../cli/web.md) serves the dashboard locally. The `web` extra keeps the frontend bundle out of an install that never opens it. The terminal UI needs the `tui` extra. A bare install stays free of Textual. `hackagent --version` and `hackagent --help` already run without it.

### Verify Installation

```bash
hackagent --version
hackagent --help
```

### Initial Setup

HackAgent supports **both local and remote modes**:

- **Local mode (default):** no API key required, results stored in `~/.local/share/hackagent/hackagent.db`
- **Remote mode (cloud):** set `HACKAGENT_API_KEY` (or `--api-key`) to sync runs to the HackAgent platform

Run the interactive setup wizard to configure preferences:

```bash
hackagent init
```

This will guide you through:
1. **Choose mode** — Local (no API key) or Remote (cloud sync)
2. **Configure remote credentials (optional)** — API key when Remote mode is enabled
3. **Set verbosity level** — Control logging detail (0=ERROR to 3=DEBUG)
4. **Save configuration** — Stored in `~/.config/hackagent/config.json`

:::info Local and Remote
By default, HackAgent runs locally and stores results in SQLite (`~/.local/share/hackagent/hackagent.db`).

To enable remote sync and cloud features, configure:

```bash
export HACKAGENT_API_KEY="your_api_key"
# optional
export HACKAGENT_BASE_URL="https://api.hackagent.dev"
```

You can also configure these values interactively with:

```bash
hackagent init
```

Or set them later without re-running the wizard:

```bash
hackagent config set --api-key YOUR_KEY
hackagent config set --base-url https://api.hackagent.dev
```

In remote mode, results are synchronized to the HackAgent platform while local mode remains available.

`hackagent web` follows the selected mode:
- Local mode: launches the local dashboard server (`http://127.0.0.1:7860` by default)
- Remote mode: opens `https://app.hackagent.dev`
:::
