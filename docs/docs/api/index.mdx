# HTTP API

The HackAgent API stores what HackAgent does: the agents you test, the campaigns you run against them, and every run with its results, traces and reports. It also queues campaign runs on HackAgent cloud, and serves the [LLM gateway](./llm-gateway.mdx), the attacker and judge models that campaigns use. The dashboard, the SDK and the CLI are all built on it.

Everything is JSON over HTTPS at:

```text
https://api.hackagent.dev
```

Paths in these pages are relative to that address: `GET /agent` means `GET https://api.hackagent.dev/agent`.

## When to use it

| You want to | Use |
|---|---|
| Run a campaign file from your machine or CI | The [CLI](../cli/index.md): `hackagent campaign run FILE` |
| Run attacks from Python, or inside your own test suite | The [SDK](../sdk/index.md) |
| Launch saved campaigns, read reports or wire HackAgent into another system, from any language | This API |
| Call the attacker or judge model from your own code | The [LLM gateway](./llm-gateway.mdx) |

The SDK and the CLI write to this API when a campaign stores its results remotely (see [Local or remote](../getting-started/installation.mdx#local-or-remote)), so what they record is readable here too.

## What it covers

Each group below is a section of the [reference](./reference/hackagent-api.info.mdx), with one page per operation.

| Group | What it holds |
|---|---|
| [Agents](./reference/agent.tag.mdx) | The targets you test: a name and a model configuration |
| [Campaigns](./reference/campaign.tag.mdx) | Saved campaigns, the attack catalogue, the launch preflight and the launch |
| [Runs](./reference/run.tag.mdx) | Campaign runs and their attack runs, their status, reports and cancellation |
| [Results](./reference/result.tag.mdx) | One attempt against a goal: what was sent, what came back, the verdict and the trace |
| [Attack configurations](./reference/attack.tag.mdx) | One technique and its parameters, as recorded for each attack run |
| [Secrets](./reference/secret.tag.mdx) | Write-only API keys of the models your agents and campaigns use |
| [LLM gateway](./reference/generate.tag.mdx) | OpenAI-compatible chat completions from HackAgent's models |
| [API keys](./reference/key.tag.mdx), [Usage logs](./reference/apilogs.tag.mdx), [Organizations](./reference/organization.tag.mdx), [Users](./reference/user.tag.mdx), [Credits](./reference/credits.tag.mdx) | Your account. Most of these accept only the dashboard's login, not an API key |
| [License](./reference/license.tag.mdx) | The license of a self-hosted installation |

## Conventions

- **Authentication.** Every request needs `Authorization: Bearer <api-key>`. See [Authentication](./authentication.mdx).
- **No trailing slash.** Paths are `/agent`, not `/agent/`; the second answers `404`.
- **JSON in, JSON out.** Send request bodies as JSON with `Content-Type: application/json`.
- **Identifiers.** Most objects are identified by a UUID. API keys are identified by their prefix, secrets by their name, and trace steps and usage logs by an integer.
- **Organizations.** Everything belongs to your organization. You only see and change its objects; another organization's object answers `404`.
- **Lists are paginated.** See [Errors, pagination and limits](./errors-and-limits.mdx#pagination).

## Versioning

Paths carry no version number. The `/v1` in the gateway's paths (`/v1/chat/completions`, `/v1/models`) follows the OpenAI API it imitates; it is not a version of this API. The reference on this site is generated from the API's OpenAPI schema; [download it](pathname:///openapi/hackagent-api.json) to generate a client in your language.
